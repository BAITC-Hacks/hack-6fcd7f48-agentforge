# Проверки проекта — 23 сентября 2026

После размещения выданных Parquet в `data/`:

```bash
uv run python -m backend.pipeline --data data --out out
uv run pytest -q
uv run ruff check backend tests scripts
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run typecheck

docker compose up --build -d --wait
```

## Расчёт и выгрузки

- Полный набор: 2 248 узлов, 3 119 рёбер, 4 840 транзакций. Три CSV содержат соответственно 2 248, 91 и 100 строк, с точными схемами из задания; все gid уникальны в таблице ролей и сохраняют int64-точность.
- Текущие роли: 265 consolidator, 68 transit, 118 distributor, 936 terminal, 2 coordinator, 859 peripheral. В top-20 — 18 consolidator, 1 peripheral, 1 distributor, 0 seed.
- Каждый consolidator не seed и не boundary, имеет минимум двух плательщиков и наблюдаемое отношение выхода ко входу ≤0,8. Каждый coordinator получает от минимум двух узлов с признаками сбора и имеет минимум двух получателей. У всех 444 граничных узлов нет ложного terminal/consolidator/coordinator.
- Максимальная длина evidence — 132 символа. Предупреждение о превышении выхода над входом есть в evidence и API; у seed отношение остаётся null. JSON сериализуется без NaN/Infinity.
- Перестановка строк официальных Parquet сохранила побайтно все три CSV. HTTP-выгрузки совпали с этими файлами, вернули 200 и attachment. Порядок приоритета не изменён пересмотром ролей и форматирования.
- В `out/` находятся только три обычных CSV. API считает снимок с `write=False`, отдаёт CSV из памяти и не создаёт каталог выгрузки. Внешний CLI-пересчёт не меняет экспорт уже запущенного API; это проверено тестом.

## Автоматические проверки

32 Python-теста прошли; последний полный прогон — 2,50 с. Ruff PASS. Внутренний расчёт с подготовкой CSV занимает около 0,6 с на предоставленном наборе; ранее измеренный полный CLI — около 1 с, запас до пяти минут значительный.

Регрессии покрывают типы и диапазон int64, переполнение денежных сумм, согласованность Parquet, изоляты, границу, неопределённое отношение seed, дедупликацию seed-путей и исключение циклов при их подсчёте. Проверяются два плательщика при удержании, запрет ложной консолидации при превышении входа, координатор от сборщиков большей минимальной глубины, независимость приоритета от роли/PageRank, обычные файлы и стабильность API-снимка.

5 frontend-тестов, lint, typecheck и production build прошли. Тесты покрывают выбор URL-режима и раскладку окрестности: изолят, отсутствующий gid, входящие/исходящие/взаимные связи, числовые tie-breaks, 20 крупнейших контрагентов и раскрытие плотной окрестности. Docker Compose собран, `up --wait` подтвердил healthy.

## Интерфейс

В IAB Chromium проверены поиск и карточки трёх показательных узлов: консолидатор `100000002398779100`, координатор `100000002224132100`, граница `100000006638021100`. Фильтр coordinator показывает два результата; в карточке первого видны два входящих сборщика и предупреждение о превышении выхода. Спорный `100000007594394100` теперь peripheral с отношением 8,54 и предупреждением о неполном балансе.

В списке приоритетов видны первые две строки evidence, полный текст доступен в карточке, tooltip и дереве доступности. Толщина обычных рёбер меняется по логарифмической шкале 1–5 относительно сумм в видимом подграфе; акцент выбранного ребра имеет ширину 6. Сумма и число операций сохраняются в детализации.

На 320×740 раскрыты расчёт приоритета и пути: ширина client/scroll — 305/305 px. На 390×844 — 375/375 px, на desktop 1440×1000 — 1440/1440 px. Обновлены снимки мобильного и настольного интерфейса; ошибок JavaScript не обнаружено. Предыдущий полный проход компоновки также охватывал 390, 768 и 1024 px, клавиатурную навигацию, пустые результаты, неправильный gid, выбор рёбер, скачивание CSV, приближение и вписывание. Сценарии и принципы — в [UI/UX-аудите](ui-ux-audit.md).

Проверки сделаны в Chromium, не на реальных телефонах; полная совместимость браузеров и WCAG не заявляется. У больших плотных графов возможны пересечения подписей. Экспорт не требует symlink, но нативный Windows-прогон не выполнялся.
